Evolving Quantum Circuits
==========================

A genetic search proposes gate sequences, Qiskit evaluates them, and
``alternative`` compares the finished candidate with a readable reference.
The complete example and its tests fit in :download:`one module
<examples/test_circuit_search.py>`. It is independent of the
:doc:`matrix-optimisation` example.

The reference implements :math:`X` as :math:`HZH`. Each genome has five slots
chosen from identity, Hadamard, Z, and X gates; identity slots do not count
toward cost. The goal is to discover a shorter circuit with the same unitary
action. This is a small demonstration of a search workflow; practical synthesis
would use the target device's gates and costs.

The Search
-----------

`DEAP <https://deap.readthedocs.io/en/master/api/algo.html>`_ supplies crossover,
mutation, selection, and the population algorithm. Qiskit's `Operator
<https://quantum.cloud.ibm.com/docs/en/guides/operator-class>`_ evaluates the
complete unitary locally, without an account or remote backend:

Fitness compares two objectives in order: unitary error first, then the gate
count of correct circuits. Every correct circuit beats every incorrect one.
Incorrect circuits retain an error distance to guide the search, but have
infinite gate cost. Giving all incorrect genomes identical fitness would lose
that guidance. Expected construction failures also receive infinity.

The matrix comparison preserves global phase: :math:`X` and :math:`-X` differ
under this contract, as their phase can become observable when controlled.
Qiskit's ``Operator.equiv`` allows global phase and would express a different
contract. The error tolerance here is :math:`10^{-12}`.

The reference seeds the population so there is always a valid fallback.
DEAP's parent-plus-offspring selection retains the best circuit, and its hall
of fame records the winner. A bounded search can retain the reference or find
a shorter circuit; it does not guarantee an optimum.

Run and Compare
----------------

From a checkout with the optional ``demo`` extra:

.. code-block:: console

   $ pip install -e '.[demo]'
   $ python docs/examples/test_circuit_search.py
   $ pytest docs/examples/test_circuit_search.py

The script prints the discovered gates and the finalists' gate counts. The
search uses Python's random generator with a seed; run it as a standalone,
sequential example. It uses one qubit and five slots to keep evaluation cheap.

Evolution happens outside the alternatives registry. ``compare_winner`` then
validates and registers the frozen candidate in a fresh set, keeping normal
calls on the reference. ``.measure()`` compares successfully returned circuits;
it cannot catch a constructor that raises before returning. Put failure handling
around construction and evaluation for a fallible generator, as ``fitness`` does
here. Promote a reviewed winner with ``default=True`` at startup in a fresh run;
see :doc:`workflow`.

Hypothesis checks known-valid circuits generated by cancelling self-inverse gate
words. The remaining tests check the real search, default preservation, phase
errors, and invalid genomes. DEAP runs the genetic evolution; Hypothesis finds
and shrinks counterexamples to correctness properties.
